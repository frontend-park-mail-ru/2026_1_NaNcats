# Foodcourt - Сервис доставки еды команды NaNcats (Фронтенд)

Фронтенд-часть распределённой микросервисной системы заказа и доставки еды (аналог Delivery Club), разработанная в рамках проектного обучения в Образовательном Центре VK (ex. Технопарк).

Особенность проекта — клиент написан на **собственном signal-based фреймворке с JSX** (без React и других UI-библиотек) и спроектирован по методологии **Feature-Sliced Design**.

## Технологический стек

*   **Язык разработки:** TypeScript 6 (strict)
*   **UI-фреймворк:** Собственный signal-based VDOM-фреймворк с JSX (без React). JSX-рантайм `@shared/lib/jsx` (Babel automatic runtime).
*   **Реактивность:** Собственная библиотека сигналов (`signal` / `computed` / `effect` / `batch`, управление жизненным циклом через owner-контексты).
*   **Роутинг:** Собственный сигнальный роутер с ленивой загрузкой страниц (code-splitting), data-loader'ами и анимациями через View Transitions API.
*   **Сетевой слой:** Fetch-обёртка `HttpClient` (управление CSRF-токеном, idempotency-keys, загрузка FormData), WebSocket для совместных корзин.
*   **PWA / Offline:** Service Worker (кэширование `network-first` для API и `stale-while-revalidate` для статики, офлайн-баннер).
*   **Карты и адреса:** Yandex Maps API (геолокация, подсказки адресов).
*   **Стили:** SCSS (Sass) + CSS-переменные, CSS Modules.
*   **Сборка:** Webpack 5 + Babel 7 (`babel-loader` / `ts-loader`), оптимизация изображений (`sharp`, генерация WebP), gzip-компрессия.
*   **Качество кода:** ESLint (с контролем границ слоёв FSD), Prettier, проверка типов `tsc --noEmit`.
*   **Документация:** JSDoc (`better-docs`).

## Архитектура системы

Проект организован по методологии **Feature-Sliced Design**. Слои выстроены сверху вниз — модуль может импортировать только из нижележащих слоёв, что контролируется правилами ESLint:

*   **`app`** — корневой шелл приложения: точка входа, переключение лейаутов (`RootLayout` / `AuthLayout` / `BareLayout`), сигнальный роутер и провайдеры (CSRF, Service Worker, статус сети).
*   **`pages`** — страницы приложения: главная (каталог ресторанов), страница ресторана (меню, рекомендации), оформление заказа, профиль, вход/регистрация, кабинет владельца ресторана, юридические страницы и `404`.
*   **`widgets`** — самостоятельные композитные блоки интерфейса: шапка, виджет корзины, выбор и подбор адреса, статус заказа, слайдер промо, игровые механики (Wordle «5 букв», «Колесо фортуны», стрик).
*   **`features`** — пользовательские сценарии: аутентификация, редактирование профиля и аватара, управление адресами / картами / промокодами, действия с корзиной.
*   **`entities`** — доменные сущности с моделью (сигнальные сторы) и API: пользователь, корзина, ресторан, адрес, заказ, достижения, карты, владелец, колесо, Wordle.
*   **`shared`** — переиспользуемое ядро, не зависящее от бизнес-логики.

### Собственный фреймворк (`src/shared/lib/`)

Вместо сторонних библиотек проект использует свой минималистичный реактивный фреймворк:

*   **`signals/`** — реактивные сигналы: `signal`, `computed`, `effect`, `batch`, owner-контексты для очистки подписок, `useStoreSignal` для связи компонентов со сторами.
*   **`vdom/`** — виртуальный DOM и рендер: `render` / `mount` / `patch`, управляющие компоненты `Show`, `For`, `Suspense`, контекст (`createContext`) и порталы (`createPortal`).
*   **`jsx/`** — JSX-рантайм (`jsx` / `jsxs`), подключаемый через `jsxImportSource: "@shared/lib/jsx"`.

Также в `shared` находятся сетевой клиент (`api/http/HttpClient.ts`), интеграция с Yandex Maps, UI-кит (модалки, скелетоны загрузки, попапы, офлайн-баннер) и утилиты (валидация, плюрализация, работа с URL и деньгами).

## Инструкция по запуску (How-to-Run)

### 1. Локальный запуск (Local Run)

Этот способ предназначен для локальной разработки и проверки работоспособности фронтенда.

#### Предварительные требования
*   Установленный **Node.js** (LTS 20+) и **npm**
*   Запущенный **бэкенд** на `http://localhost:8080` (см. backend-репозиторий) — dev-сервер проксирует на него все запросы `/api`

#### Запуск dev-сервера
1.  Установите зависимости:
    ```bash
    npm install
    ```

2.  Запустите dev-сервер:
    ```bash
    npm start
    ```

После этого приложение будет доступно по адресу `https://localhost:2033`.
Dev-сервер работает по HTTPS (самоподписанный сертификат из корня репозитория) и проксирует все запросы `/api` → `http://localhost:8080`.

#### Полезные команды разработки
*   `npm run type-check` — проверка типов (основной код + Service Worker)
*   `npm run lint` / `npm run lint:fix` — линтинг (ESLint, в т.ч. контроль границ FSD)
*   `npm run format` / `npm run format:check` — форматирование (Prettier)
*   `npm run doc` — генерация JSDoc-документации
*   `npm run build` — продакшен-сборка (включает `type-check`)

---

### 2. Развертывание на Production (Deployment)

#### Сборка
Продакшен-сборка выполняется командой:
```bash
npm run build
```
В каталог `dist/` попадает оптимизированная статика: код разбит на чанки с content-hash, изображения сжаты и сконвертированы в WebP (`sharp`), а ресурсы дополнительно упакованы gzip.

#### Раздача статики
*   На production статика из `dist/` раздаётся через **nginx** (конфигурация — `nginx.conf`) с history-fallback на `index.html` для SPA-роутинга и долгим кэшированием хэшированных ассетов.
*   В качестве альтернативы доступен лёгкий Node-сервер `server.js` (`npm run server`, порт `2033`) с теми же правилами кэширования.

#### CI/CD
Деплой фронтенда автоматизирован через **GitHub Actions** (`.github/workflows/`): пайплайн прогоняет проверки (type-check, линтинг), собирает приложение и публикует статику на тот же production-сервер, где работает бэкенд ([foodcourt.fun](https://foodcourt.fun)).
